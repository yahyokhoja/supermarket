# Переход на модель одной торговой сети

Миграция `003_single_network_access.sql` не назначает владельца и не сопоставляет склады магазинам по названию.

## Выбор владельца

После миграции оператор проверяет список активных администраторов и явно передаёт числовой идентификатор выбранного аккаунта:

```bash
DATABASE_URL=... npm run network:select-owner -- <user-id>
```

Команда принимает только активного `admin`, запрещает второго активного `owner`, пишет событие аудита и отзывает действующие сессии выбранного пользователя. Email не используется как признак владельца.

## Сопоставление старых данных

- `legacy_warehouse_store_mapping` — рабочий отчёт «старый склад → целевой магазин».
- `unresolved` означает, что решение должен принять владелец/оператор миграции.
- `confirmed` ставится только для уже существовавшей явной связи.
- После ручного решения необходимо одновременно установить `warehouses.business_store_id`, отметить строку сопоставления `confirmed` и записать автора решения.
- До подтверждения склад не попадает в область назначенного администратора. Владелец сохраняет доступ к нему для разбора наследия.

## Роли и назначения

- В установке допускается один активный `owner`.
- Доступ `admin` и `picker` вычисляется из активных строк `store_user_assignments` при каждом запросе.
- Снятие назначения действует сразу и не зависит от срока жизни JWT.
- История назначения и отзыва сохраняется в `store_assignment_audit`.
- Старые `warehouse_scopes` остаются для совместимости данных, но больше не определяют складскую область.

## Отключённые процессы

Активные API самостоятельной регистрации покупателей, корзины, публичной доставки, курьеров и кабинета стороннего продавца отвечают HTTP 410. Таблицы заказов, курьеров, продавцов и движений не удаляются: это исторические данные. Складское ядро задач сборки сохранено в коде, но убрано из основной навигации.

## HARID24

Таблицы подключений, inbox/outbox и привязок товаров сохранены без изменения внешних БД. Реальный обмен не включён.

## Миграция 004

`004_network_management.sql` добавляет телефон и архивирование магазина, явный ассортимент/цену магазина, идемпотентность сопоставления и журнал проверок архивирования. Глобальная `products.price` сохранена только для совместимости и никогда не подставляется как магазинная цена. Начальные магазинные цены автоматически не создаются.

## Открытые решения перед production

- подтвердить сопоставление каждого старого склада магазину;
- решить, какие старые `customer`, `courier` и владельцы merchant-точек становятся сотрудниками, архивом либо блокируются;
- заполнить ассортимент и явные магазинные цены перед подключением клиентов продаж;
- определить судьбу исторических заказов: отдельный owner-only архив или импорт заказов HARID24.
